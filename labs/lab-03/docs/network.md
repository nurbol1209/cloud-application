# Исследование сетевых параметров приложения

## Параметры компьютера

| Параметр | Команда | Пример значения |
| --- | --- | --- |
| Имя компьютера | `hostname` | `PC-STUDENT-01` |
| IPv4-адрес | `ipconfig` | `192.168.1.25` |
| Loopback-адрес | — | `127.0.0.1` |
| Порт приложения | — | `8000` |

Значения имени и адреса зависят от конкретного компьютера, поэтому в отчёте
указываются фактические значения, полученные при выполнении работы.

## Запуск с разными адресами привязки

```bash
# только локальный доступ
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# все сетевые интерфейсы
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## Проверка порта

```powershell
Test-NetConnection -ComputerName 127.0.0.1 -Port 8000
# TcpTestSucceeded : True
```

При использовании `127.0.0.1` сервер принимает соединения только с текущего
компьютера. При использовании `0.0.0.0` сервер принимает соединения через все
сетевые интерфейсы, а клиенты по-прежнему обращаются к нему по `127.0.0.1`
или по реальному IPv4-адресу.

## Изменение порта

```bash
python -m uvicorn app.main:app --port 8080
```

После изменения порта приложение доступно по адресу
`http://127.0.0.1:8080`, а старый адрес `http://127.0.0.1:8000` перестаёт
отвечать.

## Наблюдения

- `localhost` и `127.0.0.1` при локальном запуске указывают на один и тот же
  компьютер.
- `0.0.0.0` — адрес привязки сервера, а не адрес, который вводит клиент.
- Порт однозначно определяет сетевое приложение на узле; два процесса не могут
  одновременно слушать один и тот же порт на одном интерфейсе.
