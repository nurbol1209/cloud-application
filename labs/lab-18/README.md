# Лабораторная работа № 18. Реализация хранения файлов и объектов

## Цель

Реализовать загрузку, хранение, получение и удаление файлов, разделив
бинарное содержимое (файловое хранилище) и метаданные (PostgreSQL).

## Схема хранения

```
Файл (бинарное содержимое) ──> storage/objects/<uuid>.<ext>
Метаданные (имя, тип, размер, путь, дата) ──> таблица stored_objects
```

Клиент получает логический объект: `id` + метаданные + `download_url`.
Внутренний `storage_path` наружу не отдаётся.

## Что изменено

- `Settings`: `STORAGE_PATH` (по умолчанию `storage/objects`),
  `MAX_UPLOAD_SIZE` (5 МБ — дополнительное задание);
- ORM-модель `StoredObject` (`stored_objects`);
- миграция `0006_add_stored_objects`;
- `app/schemas/objects.py` — `StoredObjectResponse`;
- `app/services/objects.py` — сохранение блоками по 1 МБ, список,
  получение, удаление, контроль максимального размера;
- `app/routers/objects.py` — REST API `/objects`;
- `.gitignore`: `storage/`, `*.db`.

## Поля stored_objects

| Поле | Назначение |
| --- | --- |
| `id` | идентификатор объекта |
| `original_name` | исходное имя файла от клиента |
| `storage_name` | внутреннее уникальное имя (UUID + расширение) |
| `content_type` | MIME-тип |
| `size_bytes` | размер в байтах |
| `storage_path` | физический путь (внутренняя информация) |
| `created_at` | дата и время загрузки |

## Маршруты

| Метод | Адрес | Назначение |
| --- | --- | --- |
| POST | `/objects` | загрузить файл (multipart/form-data) |
| GET | `/objects` | список объектов |
| GET | `/objects/{object_id}` | метаданные объекта |
| GET | `/objects/{object_id}/download` | скачать файл |
| DELETE | `/objects/{object_id}` | удалить файл и запись БД |

## Проверка

```bash
python scripts/init_db.py
python run.py
```

Загрузка через curl:

```bash
curl -i -X POST http://127.0.0.1:8000/objects -F "file=@sample.txt"
```

Ожидаемые результаты:

- ответ `201`, в нём `original_name`, `size_bytes`, `download_url`;
- в `storage/objects` появился файл с UUID-именем;
- `GET /objects/{id}` возвращает метаданные без `storage_path`;
- `GET /objects/{id}/download` отдаёт файл под исходным именем;
- после перезапуска приложения объект остаётся доступным;
- `DELETE /objects/{id}` удаляет и запись, и файл;
- файл больше `MAX_UPLOAD_SIZE` → `413`, запись в БД не создаётся.

## Самостоятельное задание

| ID | Исходное имя | MIME-тип | Размер | В БД | В хранилище |
| --- | --- | --- | --- | --- | --- |
| 1 | `document.txt` | `text/plain` | 57 | да | да |
| 2 | `image.png` | `image/png` | 1 024 | да | да |
| 3 | `report.pdf` | `application/pdf` | 2 048 | да | да |

После проверки один объект удаляется через API; запись в БД и файл
исчезают одновременно.

## Вывод

Метаданные и бинарное содержимое хранятся раздельно: PostgreSQL знает,
*что* за объект и *где* он лежит, а файловое хранилище — *сам объект*.
Такой подход позволяет позже заменить локальный каталог внешним
объектным хранилищем без изменения REST API.
