# Лабораторная работа № 13. Проектирование базы данных

## Цель

Спроектировать реляционную модель для хранения типов сервисов и сервисов,
определить ограничения и связи.

## Что сделано

Код приложения не изменялся. Подготовлен документ
[docs/database_design.md](docs/database_design.md):

- сущность `ServiceType` (id, name, description);
- сущность `Service` (id, name, type_id, status, description, endpoint_url);
- связь `1:N` через `service_types.id → services.type_id`;
- правила целостности (PK, UNIQUE, FK, NOT NULL, CHECK);
- дополнительная сущность `ServiceStatusHistory` (самостоятельное задание).

## Ключевые решения

- название типа сервиса уникально (`UNIQUE`);
- `type_id` обязателен и ссылается на существующий тип (`FOREIGN KEY`);
- состояние ограничено значениями `running`, `maintenance`, `stopped`;
- необязательные поля (`description`, `endpoint_url`) допускают `NULL`.

## Вывод

Справочник типов устраняет дублирование и позволяет изменять описание типа
без обновления всех сервисов. Схема готова к реализации средствами SQL в
ЛР № 14.
